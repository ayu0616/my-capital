# iPhoneショートカットから歩数を自動送信する

iPhoneの「ショートカット」アプリで、ヘルスケアの歩数を毎日 `POST /api/steps` へ送信する手順です。Apple Health の書き出しファイルを取り込む機能は対象外です。

## 前提

- アプリのURL（例: `https://your-app.example.com`）を用意します。ローカルの `http://localhost:3000` はiPhoneからは開けないため、LAN内のIPアドレスかデプロイ先のURLを使ってください。
- アプリの **設定 → APIキー** でAPIキーを発行します。キーは発行時に一度だけ表示されるので、その場で控えてください。
- このAPIはセッションCookieではなく、`Authorization: Bearer <APIキー>` または `X-API-Key: <APIキー>` で認証します。アプリのパスコードやパスキーは使いません。

## ショートカットの構成

1. **ヘルスケアのサンプルを検索** を追加します。
   - 種類: `歩数`
   - 期間: 今日（開始日と終了日を今日にする）
   - 必要に応じて「すべてのサンプルを取得」にします。
   - 初回実行時にヘルスケアへのアクセス許可を求められたら許可します。
2. **統計を計算** を追加します。
   - 入力: 手順1の結果
   - 計算: `合計`
3. **日付をフォーマット** を追加し、今日の日付を `yyyy-MM-dd` 形式にします。
   - 入力: `現在の日付`
   - 日付フォーマット: `カスタム` → `yyyy-MM-dd`
   - ロケール: `en_US_POSIX` を推奨します（端末の言語設定に影響されず、`2026-11-03` のような形式になります）。
4. **辞書** を追加し、送信するJSONの中身を作ります。
   - `date`: 手順3でフォーマットした日付
   - `steps`: 手順2の合計
   - `place`（任意）: `通勤` などのメモ
5. **URLの内容を取得** を追加します。
   - URL: `https://your-app.example.com/api/steps`
   - 方法: `POST`
   - ヘッダ: `Authorization` に `Bearer <APIキー>`、`Content-Type` に `application/json` を指定
   - リクエスト本文: `JSON`
   - JSON: 手順4の辞書
6. 必要に応じて **結果を表示** を追加すると、`{"recorded":1,"dates":["2026-11-03"]}` のような応答を確認できます。

複数日分をまとめて送る場合は、辞書の代わりに次の形のJSONを送ります。`records` は最大366件です。

```json
{
  "records": [
    { "date": "2026-11-02", "steps": 7210 },
    { "date": "2026-11-03", "steps": 8432 }
  ]
}
```

## 毎晩自動で実行する

1. ショートカットアプリの **オートメーション** タブを開きます。
2. **個人用オートメーションを作成** → **時刻** を選びます。
3. 毎日23:30など、1日の歩数がほぼ確定する時刻に設定します。
4. 実行方法は **すぐに実行**（確認なし）を選びます。
5. **次へ** で作成したショートカットを選びます。
6. 必要なら「実行時に通知」を有効にして、送信結果を確認します。

日付をまたいで実行すると、その時点の「今日」の歩数が送られます。深夜に実行する場合は、日付が変わった直後ではなく、23:30など当日のうちに設定してください。

## 再送しても二重計上されない

`step_records` は日付で一意です。同じ日付のデータを再送すると、その日の歩数が上書きされるだけで、新しい行は増えません。オートメーションが失敗して手動で再実行しても、合計が二重になることはありません。再送時も最終同期日時（`updatedAt`）は現在時刻に更新されます。

## 最終同期日時の確認

ダッシュボードの **健康資本** パネルに、`最終同期 2026/11/04 07:30` のように表示されます。この表示はショートカットやAPIから記録したデータがある場合だけ出ます。手入力だけの場合は表示されません。

## うまくいかないとき

### 401（有効なAPIキーを指定してください）

- APIキーが設定画面で無効化されていないか確認します。
- ヘッダが `Authorization: Bearer <APIキー>` になっているか確認します。`Bearer` の後の半角スペースも必要です。
- `X-API-Key` を使う場合は、ヘッダ名と値を確認します。
- 送信先のURLがアプリのURLと一致しているか確認します。

### 400（入力内容が正しくありません）

応答の `issues` に、どの項目が不正かが入ります。

- `date` は `YYYY-MM-DD` 形式か（例: `2026-11-03`）。
- `steps` は0以上1,000,000以下の整数か。小数や文字列になっていないか。
- 同じ日付を複数指定していないか。
- `records` が配列で、1件以上366件以下か。
- リクエスト本文がJSONとして読めるか。`Content-Type: application/json` を付けているか。
